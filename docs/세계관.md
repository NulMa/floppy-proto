# 세계관 · 내러티브 (D-26)

기준일: 2026-08-14

> **원칙: 내러티브가 메커닉을 설명해야 한다.** 장식이면 용량만 먹고 심사에서 아무것도 못 얻는다.
> 아래 설정은 이미 구현된 규칙 4개(포맷 파동 · 용량 12칸 · 능력 파일 · 터미널)를
> 하나의 전제로 전부 설명하기 위해 역산한 것이다.

---

## 1. 전제 한 문단

> 오래된 컴퓨터 한 대가 마지막으로 꺼지기 전, 시스템이 **로우레벨 포맷**을 시작한다.
> 디스크 표면이 왼쪽부터 지워진다. 지워지면 그 안의 것은 복구되지 않는다.
>
> 너는 이 기계에 남은 마지막 빈 매체다. **1,474,560 바이트.** 그게 네가 가진 전부다.
> 지워지기 전에 남길 만한 것을 찾아 드라이브 밖으로 나가라.

---

## 2. 메커닉 ↔ 설정 대응표

**이 표가 이 문서의 핵심이다.** 새 메커닉을 넣을 때 여기에 한 줄이 안 생기면 그 메커닉은 다시 생각한다.

| 게임 규칙 | 설정 |
|---|---|
| 왼쪽에서 오는 붉은 파동 | 로우레벨 포맷이 섹터를 지우며 진행 중 |
| 용량 12칸 = 1,474,560 B | 주인공이 **말 그대로 1.44MB 플로피**다. 이건 능력치가 아니라 신체 사양 |
| 능력이 파일이고 칸을 먹는다 | 이 기계에서 돌던 유틸리티들. 자기 안에 로드해야 쓸 수 있다 |
| **능력을 넣으면 담을 공간이 준다** | 움직이려면 도구가 필요하고, 도구를 넣으면 구할 것이 줄어든다 ★ |
| 터미널에서만 로드아웃 교체 | 아직 안 지워진 정상 섹터. 여기서만 자기 자신을 다시 쓸 수 있다 |
| 터미널에서 파동이 멈춤 | 포맷은 섹터 단위로 돈다. 정상 섹터를 처리하는 동안은 진행이 멎는다 |
| 목표 디스크 | 누군가 이 기계로 만든 것. 게임 세이브 · 편지 · 노래 |
| 사망 → 마지막 터미널 | 지워진 건 너의 **그 시도**뿐이다. 마지막으로 자신을 기록한 지점부터 다시 |

## 3. 주인공

**FD-1.44** — 화면(라벨 자리)이 얼굴인 플로피디스크. BMO 계열.

- 말을 하지 않는다. **표정만 바뀐다.** 대사 대신 얼굴로 반응한다
  → 한글 폰트 문제를 피하면서 캐릭터성을 유지하는 유일한 방법이자, 실제로 더 낫다
- 셔터가 열리면 자성면이 노출된다 = 취약. 겁먹으면 셔터를 닫는다
- 쓰기 방지 탭이 몸에 달려 있고, 터미널에서만 열린다

### 표정 (아트 작업 단위)

| 상태 | 얼굴 |
|---|---|
| 평상 | 눈 두 개, 무표정 |
| 점프/공중 | 눈이 커짐 |
| 대시 | 눈이 가늘어짐, 잔상 |
| 벽 붙기 | 옆을 봄 |
| 파동이 가까움 | 흔들림, 땀 |
| 터미널 | 안도, 눈 감음 |
| 회수 성공 | 웃음 |

**얼굴 영역만 갈아끼우면 되므로 몸 스프라이트는 한 장이면 된다.** 애니메이션 비용이 여기서 크게 준다.

## 4. 텍스트 방침 ★

### 결론: **게임 내 텍스트는 전부 영문 시스템 메시지체로 간다**

근거 세 가지.

1. **기술적**: raylib 기본 폰트는 ASCII 전용. 한글은 비트맵 폰트 서브셋을 직접 만들어 넣어야 한다
   (제작 비용 + 용량). 21일 일정에서 크리티컬 패스가 아닌 곳에 쓸 시간이 아니다
2. **미학적**: 이 게임의 배경은 **도스 시절 컴퓨터 내부**다. `FORMATTING DRIVE A:` 같은 영문 시스템 메시지가
   번역체 한글보다 세계관에 정확히 맞는다. 타협이 아니라 컨셉이다
3. **가독성**: 실제 텍스트는 파일명·바이트 수·시스템 메시지뿐이다. 한국어 화자가 못 읽을 내용이 없다

> ⚠️ 단, **공모전 제출 페이지 설명과 README 는 한국어로 쓴다.** 심사자가 읽는 건 그쪽이다.
> 게임 안이 영문인 건 연출이고, 게임 밖 설명이 영문이면 그냥 불친절한 것이다.

→ 한글 폰트를 넣을지는 `D-35` 로 남긴다. 일정이 남으면 엔딩 한 줄 정도만 한글로.

## 5. 대사 — 전량

말하는 캐릭터가 없으므로 **전부 시스템 출력**이다. 아래가 게임에 들어가는 텍스트 전부다.

### 5.1 타이틀

```
        ┌─────────────────────────┐
        │   L A S T   W R I T E   │
        └─────────────────────────┘

              1,474,560 bytes free

           [ENTER] insert disk
```

### 5.2 오프닝 (타이틀에서 ENTER 후, 3초)

```
A:\> format a: /u

WARNING: ALL DATA ON NON-REMOVABLE DISK
DRIVE A: WILL BE LOST!
Proceeding with Format...

  1%_
```

→ 여기서 화면이 게임으로 전환되고, 왼쪽에서 파동이 나타난다.

### 5.3 스테이지 진입

```
SECTOR 02  -  1,474,560 bytes free
```

### 5.4 터미널 진입

```
> WRITE PROTECT DISABLED
> format halted at this sector
```

### 5.5 회수 성공 (스테이지 클리어)

```
RECOVERED:  SAVE01.DAT     73,728 bytes
            last saved 1998-04-11
```

파일마다 한 줄. **이 한 줄이 이 게임의 감정 전부다.** (§6 표)

### 5.6 사망

```
> READ ERROR
> restoring from last write...
```

### 5.7 엔딩

```
A:\> _

  4 files recovered
  1,203,712 bytes written

  disk ejected.
```

## 6. 회수 대상 — 스테이지별 목표 디스크

**여기에 감정을 싣는다.** 파일명과 한 줄 메타데이터만으로.

| # | 파일 | 크기 | 메타 한 줄 |
|---|---|---|---|
| 0 | `AUTOEXEC.BAT` | 512 B | 튜토리얼. 기계가 부팅될 때 읽던 것 |
| 1 | `SAVE01.DAT` | 73,728 B | `last saved 1998-04-11` — 누군가 끝내지 못한 게임 |
| 2 | `LETTER.TXT` | 4,096 B | `never sent` — 부치지 않은 편지 |
| 3 | `SONG.MOD` | 61,440 B | `4 channels, 3:12` — 직접 만든 트래커 곡 |
| 4 | `ME.IMG` | ? | 마지막 스테이지. **이 기계 자신의 이미지** |

마지막 하나가 이 게임의 결말이다 — 남의 것을 구하러 다니다가, 마지막에 **자기가 살던 기계 자체**를 담아 나간다.
담으려면 용량이 거의 다 필요하므로 **능력을 거의 다 버려야 한다.** 규칙과 이야기가 같은 지점에서 만난다.

> ★ 이게 §2 표의 별표 항목(`능력을 넣으면 담을 공간이 준다`)을 실제로 쓰는 유일한 스테이지다.
> 현재 구현은 목표가 칸을 안 먹는다. 마지막 스테이지에서만 먹게 하는 것이
> 규칙을 복잡하게 하지 않으면서 클라이맥스를 만드는 방법이다. → `D-36`

## 7. 제목 후보 (D-07)

| 후보 | 근거 | 판정 |
|---|---|---|
| **LAST WRITE** | 중의: 마지막 기록 / 마지막 쓰기 동작. 쓰기 방지 테마와 붙음 | ★ 추천 |
| 1,474,560 | 숫자 자체가 컨셉. 검색이 어려움 | |
| A:\RESCUE | 도스 경로 느낌. 다소 직설적 | |
| FD-1.44 | 주인공 이름 그대로. 밋밋함 | |

**추천: `LAST WRITE`.** 짧고, 발음되고, 게임을 다 하고 나면 의미가 한 겹 더 생긴다.

저장소 이름은 `last-write` 로 제안.

## 8. 하지 않는 것

- **컷신.** 텍스트 화면 전환으로 충분하다. 용량과 시간 양쪽에서 남는 게 없다
- **캐릭터 대사.** 주인공은 말하지 않는다. 표정이 대사다
- **로어 수집품.** 회수 대상 5개의 메타 한 줄이면 충분하다
- **한글 폰트** (일정 남으면 재검토 → `D-35`)
