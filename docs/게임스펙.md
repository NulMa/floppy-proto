## 3.5 지형 기믹 (2026-08-16 추가)

> **왜 추가했나:** 20 스테이지를 계측해 보니 **움직이는 위험이 하나도 없었다.**
> 적·이동발판·발사체·타이밍 게이트가 0개고, 유일한 동적 요소인 포맷 파동은
> 전역 압력이라 국소 타이밍을 못 만든다. 그래서 모든 관문이 "실행"이 아니라
> **소지품 검사**였다 — 능력만 있으면 실패할 방법이 사실상 없었다.
>
> 적을 만들지 않았다. 서사(꺼져가는 빈 컴퓨터)와 충돌하고 아트 물량이 붙는데,
> 적이 주는 것의 대부분은 **지형 타일 셋**으로 훨씬 싸게 나온다.

| 타일 | 규칙 | 무엇을 만드나 | 비용 |
|---|---|---|---|
| `T_SPIKE_A` / `T_SPIKE_B` | `spikeCycle`(1.3초)마다 번갈아 켜진다. **정확히 한쪽만** 켜져 있다 | **타이밍.** 이 게임의 유일한 리듬 축 | sim 5줄 |
| `T_UPDRAFT` | **활공 중일 때만** 위로 밀어올린다(`updraftRise` 90px/s). 통과 가능한 칸 | `glide` 의 세로 상승 역할 → **굴뚝의 두 갈래 길** | sim 5줄 |
| `T_CRUMBLE` | 밟고 `crumbleDelay`(0.35초) 뒤 사라지고 `crumbleRespawn`(2.5초) 뒤 복귀 | **국소 시간 압박.** 파동이 못 만드는 "지금 이 자리의 시계" | sim 25줄 |

### 교대 가시의 배치 문법

```
3칸 A / 3칸 안전지대 / 3칸 B / 3칸 안전지대 / 3칸 A ...
```

한쪽이 켜지면 반대쪽은 꺼지므로 **반 주기에 한 칸씩** 전진한다.

- ★ **반드시 저천장 아래에 둔다.** 개방 지형이면 그냥 뛰어넘어서 타이밍이 사라진다
- ★ 꺼진 것도 화면에 **그린다** (납작한 밑동으로). 안 그리면 없던 가시가 솟는 함정이 된다
- 대시로 뚫으려 해도 도착 지점이 켜져 있는 쪽이라 죽는다 — 기다리는 것 말고 답이 없다

### 상승 기류의 성립 조건

- ★ **기둥이 착지 발판보다 위로 뻗어야 한다.** 꼭대기가 발판과 같은 높이면
  다 올라가고도 옆으로 못 나가고 발판 옆면에 막힌다 (실제로 처음 그렇게 그렸다)
- ★ **활공을 요구해야 한다.** 능력 없이 뜨면 공짜 엘리베이터라 모든 세로 관문을 연다
  (점프패드가 마스터키였던 것과 같은 실수)

### 무너지는 발판의 함정

- ★ **되살릴 때 플레이어와 겹치는지 봐야 한다.** 안 보면 발판이 몸 안에서
  되살아나 벽에 끼인다 — 그 자리에서 영구 정지다
- ★ **리스폰할 때 전부 복원해야 한다.** 빠뜨리면 두 번째 시도부터는 발판이 없는 레벨이 된다

## 5. 터미널

| 동작 | 내용 |
|---|---|
| 로드아웃 교체 | **터미널 위에서만.** 밖에서 `1`~`5` → `DENIED` |
| 체크포인트 | 밟으면 갱신. 사망 시 여기서 재시작 |
| 포맷 정지 | 위에 있는 동안 파동이 멈추고, **최소 `formatHold`(240px)는 보장**된다 |
| **쉼 과금** | 새로 올라설 때마다 이 스테이지의 파동이 **+8% 누적**으로 빨라진다 |

> ★ **쉼 과금이 2026-08-16 에 붙었다.** 터미널은 그때까지 순수 이득이었다 —
> 체크포인트 + 파동 정지 + 로드아웃 교체를 다 주면서 대가가 없었다.
> 그래서 "밟을까 말까"가 질문이 된 적이 없다. 이 게임의 코어가 터미널인데
> 거기에 아무 긴장이 없다는 게 제일 아까운 부분이었다.
> 서사와도 맞는다 — **포맷은 멈춰준 만큼 나중에 더 빨리 온다.**

> ★ `formatHold` 는 "뒤로 밀기"가 아니다. 예전에 뒤로 확 미는 방식을 썼다가
> 파동이 화면 밖으로 나가 **아예 사라진 것처럼 보여서** 버렸다.
> 240px = 15칸이라 화면 뒤쪽(256px) 안에 남는다 — 얼마나 가까운지가 계속 보인다.

## 6. 포맷 파동

| 항목 | 값 |
|---|---|
| 속도 | `formatSpeed` = **40~74 px/s** (스테이지별, `levels.c`) |
| 실효 속도 | `formatSpeed × formatScale × (1 + formatTax × 정지횟수)` |
| 출발 간격 | `formatLead` = 400 px |
| 터미널 보장 간격 | `formatHold` = 240 px |
| 리스폰 유예 | `formatGrace` = 2.0 초 |
| 판정 | `player.x < formatX` → 사망 |

> ★★ **속도가 2026-08-16 에 통째로 올라갔다 (22~52 → 40~74).**
> 옛 값은 계측해 보니 가로 여유가 **3.4~10.9배**였다 — 즉 20 스테이지 중
> 파동이 실제 위협이 된 곳이 하나도 없었다. 게다가 `test.bat` 이
> `formatSpeed < maxSpeed × 0.5` 를 강제해서 **압박이 생길 수 있는 상한 자체가
> 설계 규칙으로 못박혀 있었다.**

## 7. 사망 / 클리어

- 사망: 가시 접촉 · 포맷 파동 접촉 · 맵 아래로 낙하 → **마지막 터미널에서 재시작** (로드아웃 유지)
- 클리어: 드라이브 슬롯(출구) 접촉.
  **보상이 걸린 스테이지(01·03·05·08)는 디스크를 회수해야 열린다**

> ★ **사망 페널티가 2026-08-16 에 생겼다.** 예전엔 리스폰이 파동을
> `spawnX − formatLead` 까지 **뒤로 밀어줬다.** 그래서 파동이 붙으면
> **일부러 죽는 게 최적 플레이**였다 — 실패에 비용이 0이었다.
> 이제 되돌리는 건 체크포인트 당시 위치까지뿐이고, 무한 사망은
> `formatGrace`(리스폰 직후 파동 정지)로만 막는다.

> ★ **출구 잠금이 없으면 진행이 막힌다.** 보상 능력은 디스크 안에 들어 있어서
> (`sim_grant_reward`) 안 줍고 클리어하면 그 능력을 영영 못 얻고,
> 그걸 `needs` 로 요구하는 다음 스테이지에서 갇힌다.
> s01 디스크를 지나치면 게임이 진행 불가였다 — 잠금 전까지 실제로 그랬다.

  효과음은 남기려는 요구가 실제로 많다.
- 볼륨 키는 **화면과 무관하게** 먹힌다 (타이틀·메뉴·플레이 전부). 누르면 하단에
  막대 오버레이가 2초간 뜬다 — 메뉴 하단과 겹치는 자리라 **불투명 판**을 깔았다.
- SFX 를 조절할 때만 샘플 소리를 한 번 낸다. 안 내면 지금 크기를 판단할 방법이 없다.
- `save.dat` 에 함께 저장한다 (포맷 v2). 키를 누를 때마다 쓰지 않고 **손을 뗀 뒤 한 번**만.

### 오디오 예산 실측 (2026-08-15)

빌드를 네 번 만들어 exe 를 직접 비교했다.

| 구성 | exe | 증가 | 예산 |
|---|---|---|---|
| 오디오 없음 | 752,640 | — | 51% |
| **+ 효과음** (절차 생성, 파일 없음) | 932,864 | **+176 KB** | **63%** |
| **+ BGM** (런타임 합성, 파일 없음) | **936,960** | **+4.0 KB** | **63%** |
| ~~+ XM 음악 (디코더 XM 만)~~ | 994,816 | +63 KB | 67% |
| ~~+ XM 음악 (디코더 전부)~~ | 1,094,144 | +162 KB | 74% |

- **+176KB 의 대부분은 miniaudio 백엔드**다. 소리를 하나라도 내는 순간 붙는 고정비고,
  효과음을 몇 개 넣든 늘지 않는다
- **효과음은 파일을 안 쓴다.** 전부 파형으로 합성한다 (`sfx.c`). 파라미터가 소리당 수십 바이트.
  wav 를 넣었으면 개당 수십 KB 였다
- **음악도 파일을 안 쓴다** (2026-08-15 결정). XM 을 넣으면 디코더 63KB + 곡 20~80KB =
  **83~143KB** 인데, `AudioStream` 에 직접 파형을 밀어넣는 시퀀서는 **4KB** 로 끝났다.
  20~35배 차이다. 출처·라이선스 관리도 필요 없어졌다
- **BGM 은 4KB 지만 스테이지 수처럼 늘어나지 않는다.** 곡을 늘려도 커지는 건
  패턴 표뿐이고, 패턴 하나가 16 B 다. 8패턴 × 3트랙 = 384 B


### 해상도 조정 · 한국어 지원 예산 실측 (2026-08-19)

현재 exe **1,030,144 B (69%) · 여유 444,416 B**. 두 기능의 **고정비**를 빌드로 직접 쟀다
(프로브 코드를 넣고 빌드 → 크기 확인 → 되돌림).

| 무엇 | 고정비 실측 | 왜 이 값인가 |
|---|---|---|
| **해상도 조정** | **+2,560 B** | `ToggleFullscreen` · `ToggleBorderlessWindowed` · `SetWindowMonitor` · `GetMonitor*` 를 전부 끌어와도 이만큼. 창 크기 코드는 이미 있다 (`main.c` 의 `scale`) |
| **한국어 — 비트맵 아틀라스** | **+2,048 B** | `LoadFontFromImage`. png 디코더는 이미 붙어 있어서 새로 낼 게 없다 |
| ~~한국어 — TTF 임베드~~ | **+38,912 B** | `LoadFontFromMemory(".ttf")` 가 **stb_truetype 를 통째로 끌어온다.** 지금은 `/OPT:REF` 가 잘라내고 있다. 폰트 바이트는 여기에 **별도로** 더 붙는다 |

**둘 다 넣어도 예산 문제가 아니다.** 판단은 이렇게 갈린다.

- **해상도 조정 — 넣는다.** 2.5KB 에 고정비가 끝나고, 지금은 모니터 높이로 배율을
  자동 결정할 뿐 사용자가 못 바꾼다 (`main.c`: `scale = (mh-140)/VIEW_H`, 2~4 로 클램프).
  전체화면이 아예 없다. 설정은 `Progress` 에 실으면 된다 — `bgmVol`/`sfxVol` 과 같은 자리다.
  ★ **정수 배율만 유지해야 한다.** 512×288 캔버스를 비정수배로 늘리면 픽셀이 깨진다
  (`아트설계.md §1`). 전체화면은 정수배 레터박스로 넣는다

- **한국어 — 넣는다면 비트맵 아틀라스로.** TTF 는 고정비만 **19배**고, 그 위에 서브셋
  폰트 바이트가 또 붙는다. 반면 이 게임은 10px 픽셀 폰트라 TTF 힌팅이 줄 게 없다.
  화면에 나가는 영문은 약 2,900자(`main.c` 1,138 + 힌트 1,736)이고, 번역하면
  **서로 다른 음절 400~600자** 규모다. 12×12 1비트 아틀라스로 **8~20 KB**,
  한글 문자열이 UTF-8 3바이트라 **+6 KB**, 토글·글리프 색인 코드 **2~4 KB**
  → **총 20~35 KB (예산의 1.4~2.4%)**

> ⚠️ **용량이 아니라 톤이 진짜 쟁점이다.** 화면 글자의 상당수가
> `AUTOEXEC.BAT` · `WRITE PROTECTED` · `DRIVE SLOT` 처럼 **DOS 화면 그 자체**다.
> 파일명은 번역하면 안 되고, `WRITE PROTECT DISABLED` 는 플로피 쓰기 보호 탭과
> 캐릭터 스프라이트(12–13번 프레임)에 직접 묶여 있다. 번역 대상은
> **힌트와 메뉴**로 한정하고 터미널 표기는 영문으로 두는 쪽이 맞다.
> 그러면 필요한 음절이 400~600 이 아니라 **200~300** 으로 줄어 아틀라스도 절반이 된다.


### 한국어 폰트 실측 — neoDGM (2026-08-19)

`art/font/` 에 받아 뒀다. 라이선스·상세는 `art/font/README.md`.

| | 값 | 판단 |
|---|---|---|
| 라이선스 | **SIL OFL 1.1** | 상업·임베드 **가능**. 고지 의무 있음 (크레딧에 넣는다) |
| `neodgm.ttf` | **651,044 B** | **여유(444,416 B)보다 크다 — 통째 임베드 불가** |
| + TTF 경로 고정비 | +38,912 B | `stb_truetype` 를 끌어온다. 지금은 `/OPT:REF` 가 잘라내고 있다 |

**그래서 아틀라스로 굽는다.** neoDGM 은 16×16 비트맵 폰트(둥근모꼴)를 TTF 로 옮긴
것이라 16px 로 찍으면 픽셀 격자에 정확히 떨어진다 — 실제로 512 음절을 렌더해 보니
**알파값이 0 과 255 두 개뿐**이었다 (안티에일리어싱 0).

| | 값 |
|---|---|
| 512 음절 아틀라스 (512×256 png) | **21,317 B** = 글리프당 41.6 B |
| 실제 필요 (힌트·메뉴만 번역) | 200~300 음절 → **8~13 KB** |
| `LoadFontFromImage` 고정비 | +2,048 B |
| 한글 문자열 (UTF-8 3바이트) | +약 6 KB |
| **합** | **약 20 KB — 예산의 1.4%** |

> ★ **남은 문제는 용량이 아니라 글자 높이다.** 한글이 16px 인데 지금 UI 는 10px 이고
> 화면은 288px 다. 한 줄이 화면의 5.5% 를 먹는다(영문 3.5%). 힌트가 2~3줄이면
> 레이아웃을 다시 재야 하고, 12px 로 줄이면 픽셀이 깨진다.

### 아트 예산 실측 (2026-08-15)

`art/floppy.png`(13프레임, 1,090 B)을 실제로 붙이고 빌드를 세 번 비교했다.

| 구성 | exe | 증가 |
|---|---|---|
| 아트 없음 (사각형으로 그림) | 936,960 | — |
| **+ png 1장** (`floppy.png` 1,090 B) | **1,000,960** | **+64,000 B** |
| + png 2장 (161 B 짜리 하나 더) | 1,001,984 | **+1,024 B** |

- **+64KB 는 png 디코더(stb_image) 고정비다.** miniaudio 와 똑같은 성격 —
  이미지를 **하나라도** 넣는 순간 붙고, 그 뒤로는 안 는다
- **두 번째 png 부터는 자기 바이트만 낸다** (161 B → +1,024 B, 섹션 정렬 때문에 올림).
  즉 남은 13장을 다 넣어도 **수십 KB** 다
- 디코더를 피하려면 raw RGBA 를 배열로 박아야 하는데, 엔딩 한 장(512×288)이
  **590 KB** 다. 디코더 64KB 를 내는 쪽이 압도적으로 싸다

**레벨당 713 B 는 추정이 아니라 실측이다** (2026-08-14).
2레벨 빌드(735,232 B)와 30레벨 빌드(755,200 B)를 만들어 exe 를 직접 비교했다.
구조체 크기로 계산한 추정치(약 480 B)보다 크다 — 정렬과 문자열 때문이다.

| 규모 | 데이터 | 예산 비중 |
|---|---|---|
| 5 스테이지 | 3.6 KB | 0.24% |
| 30 스테이지 | 21 KB | **1.45%** |
| 100 스테이지 | 70 KB | 4.7% |

> ★ **레벨 수는 용량 제약을 전혀 안 받는다.** 30개든 100개든 예산에서 의미 없는 크기다.
> 제약은 **만드는 시간과 아트**다.

**여유 473KB 는 사실상 전부 남은 아트 몫이다.** 디코더 고정비는 이미 냈고
16×16 PNG 는 장당 1KB 안팎이라 도트 물량은 바이트 제약을 받지 않는다.

## 12. 사운드

파일이 **하나도 없다.** 효과음(`sfx.c`)과 음악(`bgm.c`) 둘 다 파형을 코드로 만든다.

### 효과음 — 13종

소리 하나가 파라미터 7개(`f0 f1 dur wave duty decay vol`)다. 시작 시 한 번 합성해
`Sound` 로 올려둔다. sim 이 이벤트(`evJump`, `evLand`, …)로 알려주고 렌더 쪽이 재생한다.

### BGM — 3채널 시퀀서

| 항목 | 값 |
|---|---|
| 채널 | 리드(사각파 듀티 25%) · 베이스(사각파 듀티 50%) · 퍼커션 |
| 퍼커션 | 킥 = 150→45Hz 로 떨어지는 삼각파 · 하이햇 = 노이즈 |
| 화성 | Am - F - C - G |
| 구성 | A(조용) 4패턴 + B(한 옥타브 위, 8분음표) 4패턴 |
| 한 바퀴 | 19.2초 (100 BPM · 16분음표 × 16스텝 × 8패턴) |
| 출력 | 22050Hz 모노 16bit, `AudioStream` 에 2048샘플씩 밀어넣음 |
| 레벨 | 피크 48% FS · RMS −16 dBFS · 클리핑 0 |

> ★ **킥을 노이즈로 만들면 스네어처럼 들린다.** 급강하하는 삼각파여야 킥이다.

> ★ **패턴 4개(9.6초)는 20스테이지를 도는 동안 지겹다.** A/B 로 나눠 19.2초로 늘렸다.
> 늘리는 비용은 패턴당 16 B 라 사실상 공짜다.

`tools\bgm-preview.bat [초]` → `build\bgm-preview.wav`.
게임을 켜지 않고 곡만 들어보는 도구다. **이 wav 는 빌드에 안 들어간다.**
`tools\stub\raylib.h` 가 raylib 를 가려서 `bgm.c` 의 합성부를 그대로 재사용한다 —
곡을 두 벌 유지하면 반드시 어긋나므로 절대 복사하지 않는다.
