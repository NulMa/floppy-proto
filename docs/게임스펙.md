> 방향과 근거는 `결정사항.md`. 여기는 **기계가 판정할 수 있는 층**만 적는다.

## 1. 좌표계 · 단위

| 항목 | 값 |

| 타일 | 16 px |

> 타일을 좌표로 찍는 로직은 반드시 이걸 고려해야 한다. 여기서 영구 정지 버그가 났었다.

## 2. 용량 = 능력

**12칸 = 1,474,560 B.** 칸당 **122,880 B** (나머지 없이 떨어진다).

| 키 | 파일 | 칸 | 효과 |
|---|---|---|---|
| 1 | `jump2.exe` | 5 | 공중 점프 1회. 세기 = 지상 점프 × `jump2Mult` |
| 2 | `dash.exe` | 4 | 공중 대시. 지속 중 중력·방향입력 무시. 착지/벽잡기로 회복 |
| 3 | `glide.exe` | 4 | 하강 중 점프키 홀드 시 낙하속도 상한 = `glideFall` |
| 4 | `grip.exe` | 4 | 벽 붙기(미끄러짐) + 벽 점프. 붙으면 대시·2단점프 회복 |
| 5 | `boot.exe` | 3 | 모든 점프 세기 × `bootMult` |

합 **20칸** / 용량 **12칸** → 12칸 이내 조합 **22가지**.

## 4. 스테이지 1 (현재 유일)

### 구간 배치

| 구간 | x 범위 | 관문 | 길 A | 길 B |
|---|---|---|---|---|
| 1 | 1~31 | 세로 장벽 9칸 / 발판 3칸 | `grip` 직등 | `boot`·`jump2` 로 발판 |
| 2 | 32~61 | 평지 구덩이 6칸 ×2 | `dash` | `jump2` |
| 3 | 62~94 | 저천장 통로 4칸 구덩이 / 위층 9칸 | `grip` 으로 위층 | `dash`·`glide` 로 통로 |

터미널: x = 2, 29, 58 · 목표: x = 93

### 단독 통과 판정 (불변식 검사)

```
jump2   구간1 O  구간2 O  구간3 X
dash    구간1 X  구간2 O  구간3 O
glide   구간1 X  구간2 X  구간3 X
grip    구간1 O  구간2 X  구간3 O
boot    구간1 O  구간2 X  구간3 X
```

**단독으로 전 구간을 여는 능력 없음** ✅

### 성립 조건 (새 구간을 만들 때 지킬 것)

| 조건 | 현재값 |
|---|---|
| 위층 높이 > `jump2` 높이 | 9칸 > 4.4칸 ✅ |
| 위층 벽면을 **맨몸 점프로 잡을 수 있다** | 18px 필요 < 38px ✅ |
| 저천장 구덩이 > 저천장 도달거리 | 4칸 > 2.2칸 ✅ |
| 저천장 통로 높이 | 정확히 **2칸** |

> ★ **"벽면을 맨몸 점프로 잡을 수 있다"를 빠뜨리면 `grip` 루트가 통째로 막힌다.**
> 실제로 한 번 그렇게 만들었다. 발이 아니라 **머리**가 벽면 아랫단에 닿으면 잡힌다:
> `필요상승 = (바닥표면y - 플레이어높이) - 벽면아랫단y`

### 무엇이 예산을 먹는가

```
raylib 런타임 + CRT   약 700 KB   ← 고정. 레벨을 늘려도 안 변한다
오디오 (miniaudio)    약 180 KB   ← 소리를 켜는 순간 붙는 고정비
우리가 쓴 코드         약  50 KB
레벨 데이터            레벨당 713 B
```

### 오디오 예산 실측 (2026-08-15)

빌드를 네 번 만들어 exe 를 직접 비교했다.

| 구성 | exe | 증가 | 예산 |
|---|---|---|---|
| 오디오 없음 | 752,640 | — | 51% |
| **+ 효과음** (절차 생성, 파일 없음) | 932,864 | **+176 KB** | **63%** |
| **+ BGM** (런타임 합성, 파일 없음) | **936,960** | **+4.0 KB** | **63%** |
| ~~+ XM 음악 (디코더 XM 만)~~ | 994,816 | +63 KB | 67% |
| ~~+ XM 음악 (디코더 전부)~~ | 1,094,144 | +162 KB | 74% |

- **+176KB 의 대부분은 miniaudio 백엔드**다. 소리를 하나라도 내는 순간 붙는 고정비고,
  효과음을 몇 개 넣든 늘지 않는다
- **효과음은 파일을 안 쓴다.** 전부 파형으로 합성한다 (`sfx.c`). 파라미터가 소리당 수십 바이트.
  wav 를 넣었으면 개당 수십 KB 였다
- **음악도 파일을 안 쓴다** (2026-08-15 결정). XM 을 넣으면 디코더 63KB + 곡 20~80KB =
  **83~143KB** 인데, `AudioStream` 에 직접 파형을 밀어넣는 시퀀서는 **4KB** 로 끝났다.
  20~35배 차이다. 출처·라이선스 관리도 필요 없어졌다
- **BGM 은 4KB 지만 스테이지 수처럼 늘어나지 않는다.** 곡을 늘려도 커지는 건
  패턴 표뿐이고, 패턴 하나가 16 B 다. 8패턴 × 3트랙 = 384 B

**레벨당 713 B 는 추정이 아니라 실측이다** (2026-08-14).
2레벨 빌드(735,232 B)와 30레벨 빌드(755,200 B)를 만들어 exe 를 직접 비교했다.
구조체 크기로 계산한 추정치(약 480 B)보다 크다 — 정렬과 문자열 때문이다.

| 규모 | 데이터 | 예산 비중 |
|---|---|---|
| 5 스테이지 | 3.6 KB | 0.24% |
| 30 스테이지 | 21 KB | **1.45%** |
| 100 스테이지 | 70 KB | 4.7% |

> ★ **레벨 수는 용량 제약을 전혀 안 받는다.** 30개든 100개든 예산에서 의미 없는 크기다.
> 제약은 **만드는 시간과 아트**다.

**여유 738KB 는 사실상 전부 아트·사운드 몫이다.** 16×16 인덱스 PNG 는 장당 수 KB 라
도트 물량도 바이트 제약을 받지 않는다.

## 12. 사운드

파일이 **하나도 없다.** 효과음(`sfx.c`)과 음악(`bgm.c`) 둘 다 파형을 코드로 만든다.

### 효과음 — 13종

소리 하나가 파라미터 7개(`f0 f1 dur wave duty decay vol`)다. 시작 시 한 번 합성해
`Sound` 로 올려둔다. sim 이 이벤트(`evJump`, `evLand`, …)로 알려주고 렌더 쪽이 재생한다.

### BGM — 3채널 시퀀서

| 항목 | 값 |
|---|---|
| 채널 | 리드(사각파 듀티 25%) · 베이스(사각파 듀티 50%) · 퍼커션 |
| 퍼커션 | 킥 = 150→45Hz 로 떨어지는 삼각파 · 하이햇 = 노이즈 |
| 화성 | Am - F - C - G |
| 구성 | A(조용) 4패턴 + B(한 옥타브 위, 8분음표) 4패턴 |
| 한 바퀴 | 19.2초 (100 BPM · 16분음표 × 16스텝 × 8패턴) |
| 출력 | 22050Hz 모노 16bit, `AudioStream` 에 2048샘플씩 밀어넣음 |
| 레벨 | 피크 48% FS · RMS −16 dBFS · 클리핑 0 |

> ★ **킥을 노이즈로 만들면 스네어처럼 들린다.** 급강하하는 삼각파여야 킥이다.

> ★ **패턴 4개(9.6초)는 20스테이지를 도는 동안 지겹다.** A/B 로 나눠 19.2초로 늘렸다.
> 늘리는 비용은 패턴당 16 B 라 사실상 공짜다.

`tools\bgm-preview.bat [초]` → `build\bgm-preview.wav`.
게임을 켜지 않고 곡만 들어보는 도구다. **이 wav 는 빌드에 안 들어간다.**
`tools\stub\raylib.h` 가 raylib 를 가려서 `bgm.c` 의 합성부를 그대로 재사용한다 —
곡을 두 벌 유지하면 반드시 어긋나므로 절대 복사하지 않는다.
