# 레벨 구성 (D-27)

## 0. 전체 구조

| # | 섹터 | 회수 파일 | 가르치는 것 / 주제 | 파동 | 상태 |
|---|---|---|---|---|---|
| s00 | SECTOR 00 | `AUTOEXEC.BAT` | 조작 · 파동 · 터미널 · 능력 사용 | 22 | ✅ 구현 |
| s01 | SECTOR 01 | `SAVE01.DAT` | **전부는 못 들고 간다** · 두 갈래 길 | 34 | ✅ 구현 |
| s02 | SECTOR 02 | `LETTER.TXT` | 수직 하강 — `glide` 의 집 | 34 | ☐ |
| s03 | SECTOR 03 | `SONG.MOD` | 속도 — 파동이 바짝 붙는다 | 52 | ☐ |
| s04 | SECTOR 04 | `ME.IMG` | **목표가 칸을 먹는다** — 능력을 버려야 담긴다 | 40 | ☐ |

### 잘라야 하면 이 순서로

```
s03 → s02 → (s00·s01·s04 는 남긴다)
```

s04 를 남기는 이유: **주제가 거기서 닫힌다.** 남의 것을 구하러 다니다가
마지막에 기계 자신을 담아 나가는데, 담으려면 능력을 버려야 한다.
규칙과 이야기가 같은 지점에서 만나는 유일한 스테이지다. 이게 빠지면 그냥 플랫포머다.

## 1. s00 — AUTOEXEC.BAT (튜토리얼) ✅

한 번에 하나씩. 텍스트는 4줄뿐.

| x | 요소 | 가르치는 것 |
|---|---|---|
| 1~4 | 평지 | 이동 · 점프 |
| 5 | 터미널 ①  (`boot` 만) | 밟으면 파동이 멈춘다 = 안전 |
| 7~9 | — | "FORMAT IN PROGRESS / KEEP MOVING RIGHT" |
| 10 | 1칸 계단 | 맨몸으로 넘어진다 |
| 16~19 | **3칸 턱 (48px)** | 맨몸(38px) 불가 → `boot`(55px) 필요 |
| 24 | 터미널 ② (`boot`+`dash`) | 유틸리티는 섹터마다 다르게 있다 |
| 28~33 | **6칸 구덩이 (96px)** | `boot`(89px) 불가 → `dash`(113px) 필요 |
| 48 | 목표 | |

**"전부는 못 들고 간다"는 여기서 안 가르친다.** 능력이 2개뿐이라 12칸이 안 조인다.
튜토리얼에 제약을 앞당기면 둘 다 흐려진다. 그건 s01 이 가르친다.

## 2. s01 — SAVE01.DAT ✅

구간마다 **서로 다른 능력으로 가는 두 갈래 길.**

| 구간 | x | 길 A | 길 B |
|---|---|---|---|
| 1 | 1~31 | `grip` 으로 9칸 장벽 직등 | `boot`·`jump2` 로 3칸 발판 2개 |
| 2 | 32~61 | `dash` | `jump2` |
| 3 | 62~94 | `grip` 으로 위층(9칸) | `dash`·`glide` 로 저천장 통로 |

**핵심은 구간3 의 저천장 2칸 통로다.** 여기서만 `jump2` 가 막힌다(도달 2.2칸 < 4칸 구덩이).
`jump2` 는 높이·거리 모두 1위라 이것 말고 차단 수단이 없다.

## 3. s02 — LETTER.TXT ☐ · `glide` 의 집

### 왜 필요한가

측정에서 나온 결론(`D-33`): **`glide` 는 평지 구덩이에서 무의미하다.**
같은 높이로 건널 때는 도움이 안 되고 **아래로 내려갈 때만** 값을 한다.
지금은 s01 구간3 에서만 겨우 쓸모가 있어서, 능력 하나가 사실상 죽어 있다.

→ **세로로 긴 하강 스테이지**를 하나 만들어 `glide` 에 자리를 준다.

### 구조 (초안)

위에서 아래로 내려가는 굴뚝. 좁은 발판들이 어긋나게 배치돼 있고, 바닥은 없다(낙사).

| 관문 | 크기 | 통과 수단 |
|---|---|---|
| 하강 A | 3칸 아래 · 5칸 옆 발판 | `glide`(102px) / `dash`(113px) |
| 하강 B | 6칸 아래 · 7칸 옆 | `glide`(글라이드 시간이 길어져 여유) / `jump2` |
| 하강 C | 좁은 틈 사이로 정밀 낙하 | `glide` 로 속도 조절 / `grip` 으로 벽 타고 내려감 |
| 마지막 | 위로 3칸 복귀 | `boot`·`jump2`·`grip` |

**파동을 세로로 돌릴 것인가**는 미결(`D-37`). 가로 파동을 그대로 두면
아래로 내려가는 동안 파동이 안 따라와 압박이 사라진다.
→ 안 ①: 이 스테이지만 **위에서 내려오는 파동**  안 ②: 굴뚝을 대각선으로 배치해 가로 성분을 만든다

> 추천: **안 ②.** 파동 코드를 안 건드리고 레벨로 해결한다. 21일 일정에서 코드를 늘릴 자리가 아니다.

## 4. s03 — SONG.MOD ☐ · 속도

### 주제

**여기서 처음으로 파동이 진짜 위협이 된다** (52px/s). 지금까지는 여유가 있었다.

- 터미널 간격을 넓게. 한 번 커밋하면 오래 달려야 한다
- 관문은 쉽되 **연속**으로 배치. 멈추면 잡힌다
- `dash` 가 이동속도 자체를 올리므로 여기선 `dash` 가 유력하지만,
  `grip` 루트를 짧게 두어 **잘 타면 더 빠른** 지름길을 만든다 → 숙련도 보상

### 불변식 주의

속도 스테이지는 "가능한가"가 아니라 "빠른가"로 갈린다.
**단독 통과 가능한 능력이 생겨도 괜찮은 유일한 스테이지**지만,
그래도 `test.bat` 의 마스터키 검사는 통과시킨다 — 예외를 만들면 기준이 무너진다.

## 5. s04 — ME.IMG ☐ · 클라이맥스

### 규칙 변경 (이 스테이지에만)

**목표 디스크가 용량을 먹는다.** `ME.IMG` = 9칸.

```
들어갈 때  12칸 전부를 능력에 쓸 수 있다
목표를 담으면  9칸이 사라진다 → 능력 3칸치만 남는다 (= boot 하나)
나올 때  거의 맨몸으로 돌아와야 한다
```

→ **왕복 구조.** 회수 지점까지는 화려하게 가고, 돌아오는 길은 `boot` 하나로 풀린다.

### 성립 조건

돌아오는 경로는 **`boot` 단독(55px / 89px)으로 통과 가능**해야 한다.
가는 길과 오는 길이 물리적으로 다른 경로여야 한다는 뜻이다.
가는 길: 위로 올라가며 어려운 관문 → 회수 → **내려오는 길은 낙하 중심**(능력이 덜 필요)

> 이게 D+0 에 폐기한 "왕복 비대칭"의 재시도다. 그때는 블록 개수로 비대칭을 만들려다 실패했다.
> **이번엔 이동 능력 자체가 사라지므로 비대칭이 확실하다.** 측정으로 확인할 것.

### 미결

- 목표 칸 수 9 가 맞는가 (`D-36`)
- 담은 뒤 능력을 못 빼게 할 것인가 (터미널에서 목표를 내려놓을 수 있게 하면 긴장이 풀린다)

## 6. 구현 순서

```
1. s02 지형              ← glide 를 살리는 게 가장 급하다 (능력 하나가 죽어 있음)
2. s04 목표 칸 소모 규칙  ← 규칙 변경이라 일찍 넣고 측정해야 한다
3. s04 지형
4. s03 지형              ← 마지막. 잘릴 후보이기도 하다
5. 아트 (D-17)           ← 지형이 확정된 뒤에 그린다. 먼저 그리면 다시 그리게 된다
```

> ★ **아트를 지형보다 먼저 시작하지 않는다.** 레벨이 바뀌면 타일도 바뀐다.
> 다만 **플레이어 스프라이트와 표정은 지금 시작해도 된다** — 지형과 독립이다.

## 7. 레벨 작성법

`src/levels.c` 에 사각형 목록으로 짓는다. 96자 문자열은 손으로 못 맞춘다.

```c
static const Box S02_BOXES[] = {
    {  0,  0, 64,  1, T_SOLID },   /* x, y, w, h, 타일 */
    ...
};
static const TermSpec S02_TERMS[] = {
    {  2, 14, 0 },                 /* x, y, 장착가능 비트마스크 (0 = 전부) */
    { 30, 14, AB(AB_GLIDE) | AB(AB_GRIP) },
};
```

`avail` 마스크로 **"이 섹터엔 이 유틸리티만 남아 있다"** 를 표현한다.
튜토리얼에서 강제 학습에 썼고, 본편에서는 난이도 조절에 쓸 수 있다.
