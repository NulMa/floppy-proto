## 0-B. 해금 곡선 (구 계획)

**능력은 스테이지 마지막 디스크에서 하나씩 나온다.** 회수한 디스크 안에 유틸리티가 들어 있었다는 설정.
아직 얻지 못한 것은 **목록에 뜨지도 않는다** — 존재를 모르는 게 맞다.

`boot.exe` 만 예외로 처음부터 갖고 있다. 부팅에 쓰던 것이니 디스크에 이미 있는 게 자연스럽다.

| # | 섹터 | 회수 파일 | 주제 | 진입 시 보유 | 칸 | 보상 | 파동 | 상태 |
|---|---|---|---|---|---|---|---|---|
| s00 | SECTOR 00 | `AUTOEXEC.BAT` | 조작 · 파동 · 터미널 · 능력 사용 | boot | 3 | `dash` | 22 | ✅ |
| s01 | SECTOR 01 | `SAVE01.DAT` | 두 능력을 상황에 맞게 | boot dash | 7 | `glide` | 34 | ✅ |
| s02 | SECTOR 02 | `LETTER.TXT` | 수직 하강 — `glide` 의 집 | +glide | 11 | `grip` | 34 | ☐ |
| s03 | SECTOR 03 | `SONG.MOD` | 속도 · **여기서 12칸이 처음 조인다** | +grip | 15 | `jump2` | 52 | ☐ |
| s04 | SECTOR 04 | `ME.IMG` | **목표가 칸을 먹는다** | 전부 | 20 | — | 40 | ☐ |

> ★ **해금 곡선이 곧 난이도 곡선이다.** 능력 합계가 12칸을 넘는 s03 부터
> "무엇을 두고 갈까"가 시작된다. 그 전까지는 전부 들고 다닐 수 있어서 고민이 없다 — 의도한 것이다.
>
> ⚠️ **각 스테이지는 진입 시점의 능력만으로 깰 수 있어야 한다.** 보상형 구조에서 이게 깨지면 진행이 막힌다.
> `test.bat` 이 "해금 곡선" 절에서 검사한다.

### 용량 걱정은 안 해도 된다 (실측)

```
레벨 하나가 약 480 B  →  100개 넣어도 47 KB = 예산의 3%
```

`test.bat` 이 매번 출력한다. **레벨 수는 용량 제약을 전혀 안 받는다.**
제약은 만드는 시간과 아트다.

### 잘라야 하면 이 순서로

```
s03 → s02 → (s00·s01·s04 는 남긴다)
```

s04 를 남기는 이유: **주제가 거기서 닫힌다.** 남의 것을 구하러 다니다가
마지막에 기계 자신을 담아 나가는데, 담으려면 능력을 버려야 한다.
규칙과 이야기가 같은 지점에서 만나는 유일한 스테이지다. 이게 빠지면 그냥 플랫포머다.

## 1. s00 — AUTOEXEC.BAT (튜토리얼) ✅

쓸 수 있는 능력이 `boot` 하나뿐이라, **"고르는 법"이 아니라 "쓰는 법"만 가르친다.**

| x | 요소 | 힌트 | 가르치는 것 |
|---|---|---|---|
| 2 | 평지 | `< >` MOVE | 이동 |
| 5 | 터미널 ① | TERMINAL | 밟으면 파동이 멈춘다 = 안전 |
| 9 | — | `SPACE` JUMP | 길게 누르면 높이 뜬다 |
| 10 | 1칸 계단 | | 맨몸으로 넘어진다 |
| 12 | — | FORMAT IS COMING | 오른쪽으로 계속 가라 |
| 15~16 | 2칸 구덩이 (32px) | `SPACE` JUMP ACROSS | 맨몸 점프(75px)로 건넌다 |
| 17 | **터미널 ②** | `5` LOAD boot.exe | 턱 **바로 앞.** 못 넘고 되돌아가는 첫 경험을 막는다 |
| 19~22 | **3칸 턱 (48px)** | 3 TILES UP | 맨몸(38px) 불가 → `boot`(55px) 필요 |
| 42 | 목표 → `dash` 획득 | AUTOEXEC.BAT | |

### 힌트는 위치에 붙어서 **항상** 떠 있는다 · 박스 없이 텍스트만 ★

화면 중앙에 **한 번 띄우고 끝내면 안 된다.** 읽을 타이밍을 플레이어가 못 고르고,
파동에 쫓기는 중이면 더 그렇다. 놓치면 다시 볼 방법도 없다.
**가까이 갈 때만 뜨게 해도 놓치기 쉽다** — 화면에 들어오면 그냥 보이는 게 낫다.

```c
{ 19, 11, "1", "LOAD boot.exe", "the ledge needs it" },
/*  x   y  키      1행              2행                */
```

- 앵커 타일 위에 텍스트만. **박스·테두리·꼬리 없음**
- 배경이 없으니 지형 위에서 글자가 묻힌다 → **1px 그림자**로 읽히게 한다
- 키는 `[SPACE]` `[1]` `[<] [>]` 처럼 대괄호 텍스트. 키캡 그림도 결국 박스다
- 범위 판정 없음. 화면 밖은 카메라가 잘라낸다
- **겹치면 위/아래로 번갈아 비켜준다.** 위로만 밀면 천장에 막힌 것들이 한자리에 쌓인다
- 가로 여유는 14px. 딱 붙으면 겹치진 않아도 **두 힌트가 한 줄로 읽힌다**

> 하단 바에는 메타 키(`R restart` `F5 tune`)와 `shift dash` 만 남겼다.
> 눈에 잘 안 들어와서 가르치는 용도로는 못 쓴다.

## 2. s01 — SAVE01.DAT ✅

지형은 **다섯 능력 전부를 상정하고** 짜여 있지만, 진입 시점에는 `boot`+`dash` 뿐이다.
그래서 지금은 "두 능력을 상황에 맞게 쓴다"를 가르치고, **재방문하면 다른 길이 열린다.**

| 구간 | x | 길 A | 길 B | s01 진입 시 |
|---|---|---|---|---|
| 1 | 1~31 | `grip` 으로 9칸 장벽 직등 | `boot`·`jump2` 로 3칸 발판 2개 | `boot` |
| 2 | 32~61 | `dash` | `jump2` | `dash` |
| 3 | 62~94 | `grip` 으로 위층(9칸) | `dash`·`glide` 로 저천장 통로 | `dash` |

**핵심은 구간3 의 저천장 2칸 통로다.** 여기서만 `jump2` 가 막힌다(도달 2.2칸 < 4칸 구덩이).
`jump2` 는 높이·거리 모두 1위라 이것 말고 차단 수단이 없다.

> 이 "단독 통과 능력 없음" 불변식은 **후반 스테이지에서 의미를 갖는다.**
> s01 진입 시점에는 능력이 2개뿐이라 선택의 여지가 없다. `test.bat` 은 둘 다 검사한다 —
> ① 진입 시점 통과 가능성 ② 전 능력 보유 시 마스터키 부재.

## 3. s02 — LETTER.TXT ☐ · `glide` 의 집

### 왜 필요한가

측정에서 나온 결론(`D-33`): **`glide` 는 평지 구덩이에서 무의미하다.**
같은 높이로 건널 때는 도움이 안 되고 **아래로 내려갈 때만** 값을 한다.
지금은 s01 구간3 에서만 겨우 쓸모가 있어서, 능력 하나가 사실상 죽어 있다.

→ **세로로 긴 하강 스테이지**를 하나 만들어 `glide` 에 자리를 준다.

### 구조 (초안)

위에서 아래로 내려가는 굴뚝. 좁은 발판들이 어긋나게 배치돼 있고, 바닥은 없다(낙사).

| 관문 | 크기 | 통과 수단 |
|---|---|---|
| 하강 A | 3칸 아래 · 5칸 옆 발판 | `glide`(102px) / `dash`(113px) |
| 하강 B | 6칸 아래 · 7칸 옆 | `glide`(글라이드 시간이 길어져 여유) / `jump2` |
| 하강 C | 좁은 틈 사이로 정밀 낙하 | `glide` 로 속도 조절 / `grip` 으로 벽 타고 내려감 |
| 마지막 | 위로 3칸 복귀 | `boot`·`jump2`·`grip` |

**파동을 세로로 돌릴 것인가**는 미결(`D-37`). 가로 파동을 그대로 두면
아래로 내려가는 동안 파동이 안 따라와 압박이 사라진다.
→ 안 ①: 이 스테이지만 **위에서 내려오는 파동**  안 ②: 굴뚝을 대각선으로 배치해 가로 성분을 만든다

> 추천: **안 ②.** 파동 코드를 안 건드리고 레벨로 해결한다. 21일 일정에서 코드를 늘릴 자리가 아니다.

## 4. s03 — SONG.MOD ☐ · 속도

### 주제

**여기서 처음으로 파동이 진짜 위협이 된다** (52px/s). 지금까지는 여유가 있었다.

- 터미널 간격을 넓게. 한 번 커밋하면 오래 달려야 한다
- 관문은 쉽되 **연속**으로 배치. 멈추면 잡힌다
- `dash` 가 이동속도 자체를 올리므로 여기선 `dash` 가 유력하지만,
  `grip` 루트를 짧게 두어 **잘 타면 더 빠른** 지름길을 만든다 → 숙련도 보상

### 불변식 주의

속도 스테이지는 "가능한가"가 아니라 "빠른가"로 갈린다.
**단독 통과 가능한 능력이 생겨도 괜찮은 유일한 스테이지**지만,
그래도 `test.bat` 의 마스터키 검사는 통과시킨다 — 예외를 만들면 기준이 무너진다.

## 5. s04 — ME.IMG ☐ · 클라이맥스

### 규칙 변경 (이 스테이지에만)

**목표 디스크가 용량을 먹는다.** `ME.IMG` = 9칸.

```
들어갈 때  12칸 전부를 능력에 쓸 수 있다
목표를 담으면  9칸이 사라진다 → 능력 3칸치만 남는다 (= boot 하나)
나올 때  거의 맨몸으로 돌아와야 한다
```

→ **왕복 구조.** 회수 지점까지는 화려하게 가고, 돌아오는 길은 `boot` 하나로 풀린다.

### 성립 조건

돌아오는 경로는 **`boot` 단독(55px / 89px)으로 통과 가능**해야 한다.
가는 길과 오는 길이 물리적으로 다른 경로여야 한다는 뜻이다.
가는 길: 위로 올라가며 어려운 관문 → 회수 → **내려오는 길은 낙하 중심**(능력이 덜 필요)

> 이게 D+0 에 폐기한 "왕복 비대칭"의 재시도다. 그때는 블록 개수로 비대칭을 만들려다 실패했다.
> **이번엔 이동 능력 자체가 사라지므로 비대칭이 확실하다.** 측정으로 확인할 것.

### 미결

- 목표 칸 수 9 가 맞는가 (`D-36`)
- 담은 뒤 능력을 못 빼게 할 것인가 (터미널에서 목표를 내려놓을 수 있게 하면 긴장이 풀린다)

## 7. 레벨 작성법

`src/levels.c` 에 사각형 목록으로 짓는다. 96자 문자열은 손으로 못 맞춘다.

```c
static const Box S02_BOXES[] = {
    {  0,  0, 64,  1, T_SOLID },   /* x, y, w, h, 타일 */
    ...
};
static const TermSpec S02_TERMS[] = {
    {  2, 14, 0 },                 /* x, y, 장착가능 비트마스크 (0 = 전부) */
    { 30, 14, AB(AB_GLIDE) | AB(AB_GRIP) },
};
```

`avail` 마스크로 **"이 섹터엔 이 유틸리티만 남아 있다"** 를 표현한다.
튜토리얼에서 강제 학습에 썼고, 본편에서는 난이도 조절에 쓸 수 있다.
