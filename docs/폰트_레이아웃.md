## 1. 왜 전부 다시 재야 했나

한글은 **12px 아래로 못 내려간다.** neoDGM 은 16×16 비트맵 폰트(둥근모꼴)를 TTF 로
옮긴 것이라 16px 에서만 픽셀이 격자에 떨어진다 — 12px 로 줄이면 그냥 깨진다.
그래서 한국어를 넣는 순간 **본문이 10px → 16px (+60%)** 이 되고, 영문도 같은 폰트를
쓰므로 반각 8px 로 **가로도 약 +40%** 넓어진다.

화면은 **512 × 288** 이다. 이 크기에서 +60% 는 "조금 커지는" 게 아니라
**들어가던 것이 안 들어가는** 변화다.

## 2. 폭 계산 — 잴 필요가 거의 없다

neoDGM 16px 은 자간이 **반각 8px · 전각 16px** 로 딱 떨어진다 (실측).
그래서 폭이 그냥 `8 × 영문자수 + 16 × 한글자수` 다.

| | 한 줄 한계 |
|---|---|
| 영문만 | **64자** |
| 한글만 | **32자** |
| 실무 기준 (좌우 여백 12px) | **488px** |

`tools/font-width.ps1` 이 `strings.h` 를 전수 검사한다. 넘치면 `[OVER]` 로 찍는다.

```
powershell -File tools\font-width.ps1              # 전수 검사
powershell -File tools\font-width.ps1 -Text "문장"  # 한 줄만
```

> 실제로 이걸로 `S_MENU_KEYS` 가 **496px** 인 걸 잡았다. 눈으로는 "꽉 찼네" 정도로
> 보이는데 실제로는 8px 넘쳐서 잘리고 있었다.

## 3. 화면별 자리

### 인게임 HUD — 3줄 42px → **2줄 44px**

세 줄을 그대로 16px 로 올리면 **60px** 이 된다. 3.75 타일이라 `s08`·`s17` 같은
세로 굴뚝에서 지형을 덮는다. 그래서 셋째 줄(조작 안내)을 없애고 둘째 줄로 접었다.

```
 4..20   SECTOR 01   1,474,560 bytes free        |        12.3s  재시도 4
24..40   [용량칸 x12]  [디스크] 필수  [R] 재시작  |  WRITE PROTECT DISABLED
```

- 조작 안내에서 `shift dash` 를 뺐다. 능력 사용법은 해금 직후 교실에서 한 번만
  설명하기로 했으므로(`levels.h`) 상단 바가 또 말할 이유가 없다
- `F5` 튜닝 리로드는 개발용이라 안 적는다 (키는 살아 있다)

### 로드아웃 패널 — 폭 170 → **200**

```
px=6, pw=200          colName = px+34   colSize = px+199(우)   colTag = px+180(우)
py=52, ph = 유틸수*18 + 50
  py+4    UTILITIES
  py+24   FILE                    SIZE
  py+42   ────────────
  py+48   [아이콘] 1  boot.exe   3        (줄 간격 18)
```

> ⚠️ `colName` 을 26 으로 두면 번호와 파일명이 **2px** 밖에 안 떨어져 `1boot.exe`
> 로 붙어 보인다. 34 로 벌렸다.

### 스쳐 지나가는 문구 — 패널을 피한다

`회수` · `포맷이 멈췄다` · 거절 사유 셋 다 **터미널에 선 순간**에 뜰 수 있는데,
그때 패널이 좌상단 192px 을 차지한다. 화면 가운데에 놓으면 매번 겹친다.

```c
int flashY = w->atTerminal ? 202 : 56;
```

### 힌트 — 줄 간격 12 → **18**

앵커 위 클램프도 `y=32` → **`y=48`** (상단 바가 44px).

### 섹터 선택 — 파일명을 칸에서 **뺐다**

`AUTOEXEC.BAT` 가 12자 = **96px** 인데 칸 폭이 88px 이다. 칸을 넓히려면 열을 4개로
줄여야 하고 그러면 세로가 288px 을 넘는다. 그래서 칸은 **번호·기록·디스크**만 갖고,
파일명과 그 한 줄은 **고른 섹터 하나만** 격자 아래에 크게 띄운다.
20개를 다 작게 늘어놓는 것보다 지금 고른 것을 제대로 읽히게 하는 쪽이 정보가 많다.

```
  8..40    섹터 선택            (32px)
 50..176   격자 5열 x 4행, 칸 88x26
184..216   THEME.MOD (32px)              SECTOR 08 (우)
222..238   그가 제일 좋아하던 곡
248..264   ■쉬움 ■보통 ■어려움      20/20 클리어  디스크 20  재시도 23 (우)
268..284   [방향키] 이동  [ENTER] 시작  [ESC] 타이틀  [DEL] 초기화
```

> ⚠️ 하단 두 줄은 격자의 `x0`(=28) 이 아니라 **화면 여백 12** 를 쓴다.
> `x0` 로 맞췄더니 범례가 198px 까지 가고 집계가 196px 에서 시작해 **2px 겹쳤다.**

### 클리어 · 초기화 확인 · 엔딩

| 화면 | 자리 |
|---|---|
| 클리어 | 제목 36..68 (32px) · 디스크 76..108 · 본문 118~ (디스크 없으면 84~) |
| 초기화 확인 | 판 352×118 — 32px 제목 `기록을 모두 지운다` 가 288px 이라 320 으론 여백이 없다 |
| 엔딩 | 왼쪽 기둥만. 모니터 왼쪽 모서리가 x≈225 이라 **x=24 에서 176px** 까지가 안전선 |

## 4. 무엇을 번역하지 않았나

`strings.h` 머리에 규칙이 적혀 있다. 요약하면 **DOS 화면 그 자체는 그대로 둔다.**

| 그대로 | 왜 |
|---|---|
| `AUTOEXEC.BAT` · `boot.exe` | 파일명이다. 이 게임의 회수 대상 그 자체 |
| `SECTOR 01` · `bytes free` · `A:\>` | 도스가 그렇게 찍었다 |
| `UTILITIES` · `FILE` · `SIZE` | 도스 `DIR` 출력 형식 |
| `WRITE PROTECTED` | 실제 플로피에 적혀 있던 라벨이고, **캐릭터 12–13번 프레임의 쓰기 보호 탭**과 직접 묶여 있다 (`아트설계.md §4`) |
| `ENTER` `SPACE` `SHIFT` `ESC` `DEL` | 키 이름 |
| **파일 한 줄 설명** (`never sent`, `entries stop in march`) | **플레이버도 파일의 일부다.** `AUTOEXEC.BAT` 을 안 옮기면서 `the file this machine read first` 만 옮기면 둘이 따로 논다 (2026-08-19 결정) |

## 5. 남은 것
## 5. 무엇을 어떻게 확인했나

촬영 모드를 늘렸다. **글자 크기를 바꾸면 자리가 전부 밀리는데, 눈으로 못 보면
넘쳤는지 겹쳤는지 알 방법이 없다** — 이번에 실제로 두 번 겹쳤다.

```
floppy.exe --shottitle          타이틀
floppy.exe --shotmenu           섹터 선택
floppy.exe --shot [x] [level]   인게임 (터미널 패널 포함)
floppy.exe --shotclear 0 8      섹터 클리어
floppy.exe --shotdeath 0 6      사망
floppy.exe --shotend            엔딩
```

| | 확인 방법 |
|---|---|
| 타이틀 · 섹터 선택 · 인게임 HUD · 터미널 패널 · 클리어 · 사망 · 엔딩 | **눈으로 봤다** |
| 볼륨 오버레이 · 초기화 확인창 | 폭은 `font-width.ps1` 로 488px 이내 확인, 세로는 계산만 |

> 이번에 눈으로 봐서 잡은 것 셋:
> ① `붙` 글리프가 통째로 빠져 화면에 `?` 로 나왔다 (아틀라스 도구 정규식 버그)
> ② 범례와 집계가 2px 겹쳤다
> ③ 체크포인트 문구가 로드아웃 패널을 덮었다
>
> **셋 다 계산으로는 안 걸렸을 것들이다.**

## 6. 언어 전환 (2026-08-19, 2차)

한국어로 **교체**한 게 아니라 **둘 다 지원**한다. 처음엔 교체만 해 놓고 전환 수단을
안 만들었다 — 그건 그냥 빠뜨린 것이다.

### 어디서 바꾸나

`[F1]` — **어느 화면에서든** 먹힌다. 볼륨(`[ ]` `- =` `M`)과 같은 방식이다.
설정 화면을 따로 만들지 않는 게 이 게임의 방식이고, 무엇보다
**글자를 못 읽는 사람이 설정 화면을 찾아 들어갈 수는 없다.**

키 안내는 두 곳에 적어 둔다.

| 화면 | 자리 | 표시 |
|---|---|---|
| 타이틀 | 볼륨 키 줄 끝 | `... [M] 음소거   [F1] ENGLISH` |
| 섹터 선택 | 우측 상단 (y=14) | `[F1] 한국어` |

> ★ **지금 언어가 아니라 "바뀔 언어"의 이름을, 그 언어의 글자로 보여준다.**
> 한국어일 때 `[F1] ENGLISH`, 영어일 때 `[F1] 한국어`.
> 무슨 일이 일어나는지 번역 없이 읽힌다 — 이 줄만은 어느 언어도 아니어야 한다.

선택은 세이브에 남는다 (`save.dat` **v3**). 옛 세이브(v1·v2)는 그대로 읽고
언어만 기본값을 채운다 — 설정 하나 때문에 남의 클리어 기록을 날리지 않는다.

### 구조

```
lang.h        Lang 열거형 · extern g_lang · TR(en, ko) 매크로
levels.c      int g_lang = LANG_DEFAULT;   ← test.c 도 이 파일을 링크한다
strings.h     #define S_X TR("english", "한국어")   ← 두 언어가 같은 줄에
levels.h      HintSpec { l1en, l1ko, l2en, l2ko }  ·  Level { metaEn, metaKo }
```

★ **두 언어를 같은 줄에 둔다.** 파일을 갈라 두면 영문만 고치고 한국어를 잊는 일이
반드시 생긴다. `TR` 이 그대로 `const char *` 로 펼쳐져서 쓰는 쪽은 언어를 몰라도 된다.

> ⚠️ `TR` 은 `g_lang` 을 읽는 **런타임 식**이라 static 초기화에 못 들어간다.
> `static const char *TIER_NAME[3] = { S_TIER_EASY, ... }` 가 컴파일 에러가 나서
> `tier_name(k)` 함수로 뺐다.

### 도구가 두 언어를 다 본다

`tools/font-width.ps1` 이 `TR(en, ko)` 를 풀어서 **양쪽 다** 재고, 추가로
**포맷 지정자를 대조**한다.

```
101줄 검사 · 한계 488 px · 넘치는 줄 0개
포맷 지정자 en/ko 일치 — 어긋난 줄 없음
```

★ 포맷 대조가 특히 중요하다. `%d` 하나가 번역에서 빠지면 화면이 깨지는 게 아니라
`snprintf` 가 스택을 엉뚱하게 읽어서 **그냥 죽는다.** 번역은 사람이 하는 일이라
이건 도구가 봐야 한다.
