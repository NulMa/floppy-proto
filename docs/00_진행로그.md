**막힌 것 / 그 원인**

- 공식 raylib 배포 lib 이 `/MD`(동적 CRT) 빌드라 `/MT` 링크가 깨졌다 (`__imp_realloc` 미해결).
  → `/MD` 로 도망가면 VC++ 재배포 패키지 의존이 생겨 제출용으로 못 쓴다.
  **raylib 을 소스에서 `/MT` 로 직접 빌드** (`build-raylib.bat`). 용량 최적화에도 어차피 필요한 작업이었다
- `.bat` 파일을 LF 개행으로 써서 cmd 가 토큰을 깨먹었다. CRLF 필수

**판단**

| 무엇을 | 어떻게 정했나 | 근거 |
|---|---|---|
| 엔진 | C + raylib 정적 | 런타임 있는 엔진은 1.44MB 에 물리적으로 불가 |
| CRT | `/MT` 정적 | 재배포 패키지 없이 실행돼야 함 |
| 구조 | `sim.c`(로직) / `main.c`(렌더) 분리 | 헤드리스 검증·밸런스 루프의 전제. C 에서는 파일 분리만으로 공짜 |
| 감각 수치 | `tune.txt` 외부화 + F5 핫리로드 | 기획이 코드 안 건드리고 조정하기 위함 |

**측정으로 잡은 것**

- 봇 왕복 결과 **갈 때 4.3s / 올 때 3.5s, 사망 0**.
  설계 의도였던 "목표가 8칸을 먹어서 돌아오는 길이 어려워진다"가 **실제로는 성립하지 않았다.**

## 2026-08-14 (D+1) — 코어 2회 번복, 방향 확정

**한 일**

- 조작 방식 변경 (토글+E 수동 → Shift 홀드 + 자동 설치) — 이후 폐기
- **코어 전면 교체**: 블록 다리 → **능력 로드아웃**
- 능력 5종 구현: `jump2` `dash` `glide` `grip` `boot` (합 20칸 / 용량 12칸)
- 맵 96x18 확장 + 가로 스크롤 카메라
- **터미널 잠금** — 로드아웃은 터미널 위에서만 교체 가능. 체크포인트 겸용
- **포맷 파동** — 왼쪽에서 삭제 영역이 전진. 터미널 위에서는 정지
- 3구간 레벨 (구간마다 서로 다른 능력으로 가는 두 갈래 길)
- 테스트를 "관문 크기 vs 물리 수치" 대조 방식으로 재작성

**막힌 것 / 그 원인**

- **블록 설치 시 영구 정지 버그.** 설치 위치를 플레이어 *중심* 좌표로 계산했는데,
  플레이어 12~14px / 타일 16px 이라 대부분의 시간 두 칸에 걸쳐 서 있다.
  이미 몸이 걸친 칸에 블록이 놓이면 `rect_hits_solid` 가 항상 참 → X·Y 이동 동시 차단.
  → 조준을 **몸이 안 걸친 첫 칸**(`lead_col`)으로 바꾸고, 설치 전 AABB 교차 검사, 갇히면 밀어내는 안전망까지 3중으로 막음
- **레벨 검증 코드 자체가 틀려 있었다.** 특정 행 하나만 보고 구덩이를 재서,
  실제 4칸 구덩이를 17칸으로 측정. 바닥 높이가 변하는 구간에서는 "발 디딜 곳이 없는 열"로 세야 함
- **구간3 의 두 갈래 중 하나가 통째로 막혀 있었다.** 위층 덩어리 아랫면이 바닥에서 4칸이라
  `grip` 등반을 시작할 벽면에 손이 안 닿았다. 덩어리를 `row12` 까지 내려 18px 상승으로 잡히게 수정

**번복 ①** — 코어 메커닉

> ~~플로피가 블록을 흡수·기록해 자기장 협곡에 다리를 놓는다. 목표 디스크가 8칸을 먹으므로
> 돌아오는 길은 블록이 모자라 훨씬 어려워진다~~
> → **폐기.** 능력 로드아웃 방식으로 교체.

근거 두 가지.

1. **측정**: 봇 왕복 4.3s vs 3.5s 로 왕복 비대칭이 없었다. 설계의 핵심 주장이 수치로 반증됨
2. **실플레이**: "재미랄 게 딱히 안 느껴진다" (사람 판정)

사후 정리하면 — **블록 설치는 이동을 멈추게 하는 동사**였다. 플랫포머의 재미는 이동에 있는데
코어 동사가 이동을 끊고 있었으니 방향이 반대였다. 능력은 **이동 자체를 바꾸는 동사**라 결이 맞는다.

**번복 ②** — 조작 방식

> ~~보호/쓰기 모드를 Shift 로 토글하고 E 로 흡수·기록~~
> → Shift 홀드 + 자동 설치로 바꿈 → **번복 ① 로 코어가 사라지면서 같이 폐기됨**

이 중간 단계는 살아남지 못했지만 남길 가치가 있다:
한 칸 전진에 `Shift`→`E`→걷기→`Shift` **4입력**이 필요했던 게 "조작감이 매우 불편"의 실체였다.
**입력 수를 세는 것만으로 조작 설계 문제를 진단할 수 있다.**

**판단**

| 무엇을 | 어떻게 정했나 | 근거 |
|---|---|---|
| 코어 | 능력 로드아웃 (용량 12칸) | 위 번복 ① |
| 로드아웃 교체 | **터미널에서만** | 아무 데서나 바꾸면 커밋이 없고, 커밋이 없으면 전략이 없다 |
| 추격 요소 | **포맷 파동**(좌→우 전진) | 적 AI 보다 싸고 결정론적. 디스크 포맷이라는 테마에 정확히 붙음 |
| 레벨 구조 | 구간마다 **두 갈래 길** | 관문마다 정답을 여러 개 두는 방식으로는 마스터키 문제가 안 풀린다 (아래) |

**측정으로 잡은 것 — 마스터키 문제**

관문마다 통과 수단을 여러 개 두는 1차 레벨에서, 테스트가 잡아냈다:

```
jump2 는 높이(4.4칸)도 거리(8.9칸)도 전 능력 중 1위 → 모든 관문의 상위호환
```

**튜닝으로 안 풀린다.** 2단 점프는 본질적으로 체공시간을 두 배로 만들어 높이와 거리를 동시에 먹는다.
길 자체를 갈라야 한다는 결론이 여기서 나왔다. 갈라놓은 뒤 재측정:

```
jump2  구간1 O  구간2 O  구간3 X      <- 저천장 통로(도달 2.2칸 < 4칸) + 위층 9칸에 막힘
dash   구간1 X  구간2 O  구간3 O
glide  구간1 X  구간2 X  구간3 X
grip   구간1 O  구간2 X  구간3 O
boot   구간1 O  구간2 X  구간3 X
→ 단독 통과 능력 없음. 12칸에 들어가는 로드아웃 22가지
```
