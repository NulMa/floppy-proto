### ☑ D-29. 파동 속도 곡선 — **결정** (2026-08-16)

스테이지별 `formatSpeed` **40~74 px/s** + **쉼 과금**(터미널에 새로 올라설 때마다 +8% 누적).

계측이 근거다. 옛 값(22~52)은 가로 여유가 **3.4~10.9배**여서
20 스테이지 중 파동이 실제 위협이 된 곳이 하나도 없었다.
게다가 `test.bat` 이 `formatSpeed < maxSpeed × 0.5` 를 강제해서
**압박이 생길 수 있는 상한 자체가 설계 규칙으로 못박혀 있었다** (→ 0.70 으로 완화).

**"시간이 지나면 가속" 안은 폐기했다.** 쉼 과금 쪽이 더 낫다 —
터미널은 그때까지 순수 이득이라 "밟을까 말까"가 질문이 된 적이 없었는데,
쉬는 데 값을 붙이면 이 게임의 코어에 처음으로 긴장이 생긴다.
서사와도 맞는다: 포맷은 멈춰준 만큼 나중에 더 빨리 온다.

곁들여 `formatHold`(터미널이 보장하는 최소 간격 240px)를 넣었다.
멈추기만 하던 시절엔 파동이 바짝 붙은 채 도착할 수 있었고,
그러면 뒤이은 등반 구간이 통째로 불가능해졌다.

### ☑ D-30. 실패 처리 — **결정** (2026-08-16)

**목숨 제한도 랭킹도 안 넣는다. 대신 "죽는 것이 이득이던 것"을 끊었다.**

`sim.c` 의 리스폰이 파동을 `spawnX − formatLead` 까지 **뒤로 밀어주고 있었다.**
그래서 파동이 붙으면 **일부러 죽는 게 최적 플레이**였다 — 실패에 비용이 0이었다.
목숨을 몇 개 주든 이 구조에서는 의미가 안 생긴다.

- 되돌리는 것은 **체크포인트 당시 위치까지뿐.** 그 이상은 안 준다
- 무한 사망만 `formatGrace`(리스폰 직후 2초 파동 정지)로 막는다
- 터미널 위에서는 파동이 아예 안 오므로 유예가 끝나도 언제든 다시 준비할 수 있다

> 랭킹·기록은 `D-21`(제출) 이후 여유가 남으면 본다. 지금은 실패에 값이 붙은 것으로 충분하다.

## C. 파이프라인 · 기술

### ☑ D-46. 해상도 — **Alt+Enter 전체화면 하나만** (2026-08-19)

배율 선택 UI 는 안 만든다. 창 배율은 지금처럼 모니터 높이로 자동(×2~×4)이고,
전체화면은 **Alt+Enter** 하나다 — 도스·윈도우에서 30년째 같은 키라 안내가 필요 없다.

`ToggleBorderlessWindowed()` 를 쓴다. 진짜 전체화면은 모니터 모드를 바꿔서 전환할 때
화면이 꺼지고 알트탭이 느린데, 512x288 을 정수배로 키우는 게임이라 얻을 게 없다.

**출력을 정수 배율 + 레터박스로 바꿨다.** 1920x1080 은 288 의 3.75배라 그대로 늘이면
픽셀 크기가 3px/4px 로 갈려 글자가 울퉁불퉁해진다. 3배로 두고 위아래를 검게 남긴다.

| | |
|---|---|
| 고정비 실측 | **+3,072 B** (여유의 0.7%) |
| 안 만든 것 | 배율 선택 UI · 해상도 목록 · 설정 화면 |

> ⚠️ **Alt+Enter 는 사람이 눌러 봐야 한다.** 촬영 모드로는 확인이 안 된다 —
> 레터박스 계산과 창 복귀는 코드로만 확인했다.

`>nul` 이 stdout 을 통째로 버려서 컴파일이 깨지면 **아무것도 안 찍히고 조용히 종료**했다.

성공하면 예전처럼 조용하다. 일부러 깨뜨려서 에러가 뜨는 것까지 확인했다.

### ☐ D-38. 플로피 캐릭터의 얼굴 비율

화면(얼굴)이 몸의 몇 %인가. BMO 는 약 60%. 이 게임은 12×14 라 얼굴이 크면
표정이 살고 몸이 죽는다. **표정이 이 캐릭터의 전부**라는 게 `아트설계.md` §4 의 전제다.

### ☐ D-39. 배경 격자를 섹터마다 바꿀 것인가

`아트설계.md` §2 는 "20 스테이지가 전부 디스크 한 장 안"이라 **반대** 입장이다.
다만 20판을 같은 배경으로 도는 단조로움은 실제 위험이다.
절충안: 무늬는 고정하고 **밝기만** 섹터가 깊어질수록 낮춘다.

### ☐ D-40. 엔딩 일러스트를 그릴 것인가

안 그리면 텍스트 엔딩. A·B순위가 끝난 뒤에 남은 날짜를 보고 정한다.

### ☑ 팔레트 제한 — **없앤다** (2026-08-15)

`아트설계.md` §2 의 16색은 **용량 걱정 때문에 걸어둔 제한**이었다. 그 걱정이 근거가 없다.

| | |
|---|---|
| 그려진 `floppy.png` (13프레임, 20색) | **1,090 B** |
| 같은 그림을 인덱스 컬러로 저장 | **1,669 B** — 오히려 크다 |

색 수는 이 규모에서 예산에 아무 영향이 없다. **16색 표는 권장이지 규칙이 아니다.**
그림이 표를 벗어나면 표를 고친다. 실제로 쓰인 색은 `아트설계.md` §2 에 기록해 뒀다 —
**나머지 13장이 같은 세계로 보이게** 하려는 참고용이지 준수 대상이 아니다.
같은 이유로 터미널 프레임의 붉은 눈(`#F35E5A`)도 그대로 간다.

남는 건 용량이 아니라 **읽히느냐**뿐이다. 하나만 확인한다:
**흑백으로 바꿔서 배경과 지형이 갈리는가** (`bg_tile` 밝은 쪽 `#2A2A39` ↔ 지형).

### ☐ D-41. 표정 2차 패스를 할 것인가

`아트설계.md` §4 는 **"표정이 이 캐릭터의 전부"**를 전제로 쓰였는데,
실제로 그려진 13칸은 **눈이 전부 같은 2×2 두 개**다(위치만 움직인다). 입은 없다.
상태를 가르는 건 실루엣이고, 색으로 갈리는 건 터미널(12–13) 뿐이다.

실루엣만으로도 상승·하강·벽붙기는 구분된다 — 즉 **지금 상태로도 게임은 성립한다.**
표정을 얹으면 캐릭터가 살지만 13칸을 다시 건드리는 일이고, 그 시간은 아직 안 그린
13장에서 나온다. **A순위(지형·터미널·디스크·출구)가 끝난 뒤에 정한다.**

## F. 구현이 만들어낸 미결

> **기획을 덜 한 게 아니라, 재보기 전에는 물어볼 수 없었던 질문이다.**

### ☑ D-33. `glide` 의 존재 이유 — **결정** (2026-08-16)

**상승 기류(`T_UPDRAFT`)를 넣어서 활공에 세로 *상승* 역할을 붙였다.** sim 5줄.

문제는 "활공이 하강에서만 값을 한다"였고, 그 지형이 몇 스테이지에만 있었다.
능력을 교체하는 대신 **쓰임을 늘리는 쪽**을 골랐다 — 부수 효과가 더 컸기 때문이다:

> 그때까지 세로 이동 수단이 `grip` **하나뿐**이라 굴뚝 6개가 전부 똑같았다.
> 기류가 생기니 **"굴뚝을 벽으로 오를까 바람으로 오를까"** 라는 두 갈래 길이
> 데이터만으로 만들어진다. `s06`·`s08`·`s17`·`s19` 가 이걸로 갈린다.

성립 조건 둘 (`게임스펙.md §3.5`):
- **활공을 요구해야 한다** — 없으면 공짜 엘리베이터라 모든 세로 관문을 연다
- **기둥이 착지 발판보다 위로 뻗어야 한다** — 꼭대기가 같으면 다 올라가고도 옆으로 못 나간다

### ☐ D-35. 한글 폰트를 넣을 것인가

현재 게임 내 텍스트는 **전량 영문 시스템 메시지체**다 (`세계관.md` §4).
raylib 기본 폰트가 ASCII 전용이라 한글은 비트맵 폰트 서브셋을 직접 만들어야 한다.

- 지금 방침이 미학적으로도 낫다고 판단했지만, **한국 공모전**이라는 점은 남는 변수
- 넣는다면: 필요한 글자만 서브셋한 8×8 또는 12×12 비트맵. 엔딩 한 줄 정도만
- 비용: 폰트 제작 + 렌더러. 용량은 10~20KB 로 부담 없음

> 판단 시점: s04 까지 구현이 끝나고 일정이 남았을 때. 크리티컬 패스가 아니다.

### ☑ D-36. `ME.IMG` 가 먹는 칸 수 — **9칸으로 확정** (2026-08-16)

8칸(4칸 남음)이면 능력 하나를 더 고를 수 있어 선택지가 생기지만,
**그러면 "전부 버린다"는 결말이 흐려진다.** 3칸 = `boot.exe` 정확히 하나가
처음 시작할 때 갖고 있던 그것이라는 점이 이 스테이지의 전부다.
선택지는 앞의 19 스테이지에서 이미 충분히 준다.

- 내려놓기는 **가능하다** — 터미널에서 디스크도 빼는 게 아니라, 담기 전에
  능력을 비우러 되돌아가는 구조다. 디스크(x76) 바로 앞에 터미널(x69)을 둬서
  8칸만 되돌아가면 된다 (파동이 그동안 멈춘다)
- **성립 조건 검사를 `test.bat` 에 넣었다** (이 항목이 요구하던 것):
  디스크 지점부터 출구까지의 최대 구덩이 ≤ `boot` 거리, 최대 턱 ≤ `boot` 높이

> 곁들여 s20 의 관문을 바꿨다. 원래 `needs` 가 boot+dash+jump2 = **정확히 12칸**이라
> 클라이맥스에서 로드아웃 선택지가 0이 됐다 — 코어가 꺼진 채로 끝나는 셈이었다.
> 뜬 선반(jump2 관문)을 빼고 9·10칸 구덩이로 바꿔 `needs` 를 7칸으로 내렸다.
> jump2 관문은 `s09` 에 그대로 남아 있다.

### ☐ D-37. s02 의 파동 방향

세로 하강 스테이지에서 가로 파동은 안 따라온다 → 압박이 사라진다.

| 안 | 방법 | 비용 |
|---|---|---|
| ① | 이 스테이지만 위에서 내려오는 파동 | 파동 코드 수정 |
| ② | 굴뚝을 대각선으로 배치해 가로 성분을 만든다 | 레벨만 |

> 추천 **②.** 21일 일정에서 코드를 늘릴 자리가 아니다.

### ☐ D-34. 터미널에서 앞 구간이 실제로 보이는가

**터미널에 서면 다음 구간이 화면 밖일 수 있다.** 미확인.
